01 · Context

Language models are reaching game worlds

Characters that talk back, advisors that reason about the game state, quests that react to the player. Large language models make this possible, but a game is a strict, real-time system with rules it cannot break.

New kinds of gameplay

Model-driven agents can hold conversations, explain choices and suggest actions inside the game, instead of following fixed dialogue trees.

Unity as the platform

Arandu targets Unity 6 (6000.3.16f1). The plugin lives in C# assemblies that any Unity project can reference.

A research pivot

The project started as a latency comparison of LLMs. It moved to a broader goal: reusable infrastructure for agents in Unity games.

02 · Problem

Connecting a model to a game is easy. Doing it safely is not.

A quick integration usually calls a provider API straight from gameplay code. That works for a demo, but it creates problems that grow with the project.

P1

Provider lock-in

HTTP calls, JSON formats and model quirks end up mixed with gameplay. Switching provider or model means rewriting game code.

P2

Unsafe effects

If the model can change the game state directly, a wrong or invented answer can break rules, spend resources or corrupt progress.

P3

No limits

Without explicit budgets, a request can loop on tool calls, grow its context or take too long. Time, calls, context and cost need bounds.

P4

Hard to inspect

When something fails, developers need to know what was asked, what the model proposed, what was applied and why it stopped.

Guiding question How can a Unity game use model-driven agents in a way that is reusable, bounded and inspectable, while the game keeps full authority over its own state?

03 · Proposed solution

A plugin that separates orchestration, providers and gameplay

Arandu coordinates a finite request between the game and a model. Game services stay in charge: they validate and apply every action the model proposes.

1Game request
→
2Agent + skill + context
→
3Model response or tool proposal
→
4Registered tool + game authority
→
5Observation → next turn or result

The model proposes. Authoritative game code decides. Cancellation cannot undo an action already applied.

Plugin foundation

Arandu.Core Portable agent runtime: requests, sessions, limits, tool loop, results and receipts.
Arandu.ModelAdapter Shared base to connect any model backend. No HTTP or vendor SDK dependency.
Arandu.Integration Unity bridge: Inspector setup, C# tool and skill registration, scoped lifetimes.
Arandu.Editor Editor-only monitor to validate configuration and inspect requests and receipts.

Built on top, kept separate

ExampleAdapters / Gemini Model selection, bounded paginated model discovery and stateless Interactions.
ExampleAdapters / Groq Chat Completions and model listing, with a GPT-OSS 120B profile.
Samples / ThroneRoom First standalone gameplay sample, built with a six-module sample architecture.

The foundation never depends on the examples. Developers can write their own adapter for an embedded engine, a local service or any external API.

Core concepts

Agent

An agent has its own configuration and permissions. Several independent agents can run in the same game, each with separate sessions.

What keeps it bounded and inspectable

Explicit limits

Time, calls, context and cost budgets per request. Skills can narrow them further.

Context compaction

On by default. Fits the complete request into the budget of the selected model.

Retry pacing

Fixed retry by default, with opt-in backoff, jitter and support for Retry-After.

Debug mode

Separate diagnostic build with request timing, failure reports and file capture.

04 · Sample game

ThroneRoom: rule a kingdom with a scheming advisor

The sample shows the plugin inside a real gameplay loop. You are the Monarch for a 5-day reign. Each day brings one crisis, drawn from 20 authored crises, and an AI advisor who may not tell the whole truth.

Opening counsel

Grand Vizier Malakor presents the petition with a biased framing and proposes a Royal Edict draft through a tool.

Send royal scouts

Pay gold to reveal verified facts. The context changes, the skill switches, and Malakor proposes an honest remedy.

Audience chamber

Question the Vizier in free chat. From day two he can also read the history of the reign.

Your decision

Sign the edict, veto the draft or ignore the crisis. The game applies the costs and effects, never the model.
